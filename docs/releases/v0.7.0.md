# automerge-cpp v0.7.0

Upstream compatibility with automerge-rs, sync, persistence and history.

## What it includes

- **Upstream-compatible change hashes and chunk encoding:** a change made here has the same hash and
  bytes as automerge-rs, checked against fixtures generated by automerge-rs
  ([`docs/change-hashes.md`](../change-hashes.md)).
- **The upstream sync wire format:** messages, bloom filters and persisted sync state that interoperate
  with automerge-rs ([`docs/sync-wire-format.md`](../sync-wire-format.md)).
- **A bidirectional fixture sweep:** documents written by automerge-rs load here, and documents written
  here load in automerge-rs ([`docs/fixtures.md`](../fixtures.md)). The reverse check runs when `cargo`
  is installed.
- **Idempotent change application:** applying an external change twice is harmless, and changes whose
  dependencies have not arrived wait in a queue ([`docs/change-application.md`](../change-application.md)).
- **Transaction rollback:** a transaction can be discarded, leaving the document as it was
  ([`docs/transactions/rollback.md`](../transactions/rollback.md)).
- **Actor ids from the operating system's random source** (CSPRNG).
- **Unicode scalar values for text:** text positions and lengths count Unicode scalar values, as upstream
  does ([`docs/text/unicode-scalar-values.md`](../text/unicode-scalar-values.md)).
- **Patches for remote changes:** applying another peer's changes reports what changed
  ([`docs/remote-patches.md`](../remote-patches.md)).
- **Incremental persistence and change queries:** save only what changed since the last save, load
  incremental saves, and ask which changes a document holds ([`docs/incremental-save.md`](../incremental-save.md)).
- **Commit metadata:** a message and a time on each commit.
- **Shallow history checkpoints and compact saves** ([`docs/history-compaction.md`](../history-compaction.md)).
- **Deferred, cached change chunk encoding:** a change is encoded once, when it is first needed.
- **Expected errors at public boundaries:** calls that can fail return `std::expected` with an error
  ([`docs/errors.md`](../errors.md)).
- **Tooling:** `.clang-format` and the formatting rule, a docs index, `AGENTS.md`, and an SBOM
  (`sbom.spdx.json`, `sbom.cdx.json`, made by `tools/sbom.py`).
- **CI:** the hosted workflows use C++23-capable toolchains (GCC 14, Clang 19).

## Breaking changes

- **Error returns:** the apply and load functions return `std::expected` instead of their old result
  types, so code that calls them must check the result.
- **Old saves:** documents saved before the change-hash change (by v0.6.0 or earlier) do not load.
  Change hashes are now computed the upstream way.

## Known issues

- **Security:** none known.
